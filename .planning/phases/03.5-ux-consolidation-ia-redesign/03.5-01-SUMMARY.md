## Decisions Made
- **Direct DDL via pg client instead of drizzle-kit push:** The database had extra columns not in schema.ts (`guardian_auth_id`, `family_label` on assistants; `auth_id` on profile) that drizzle-kit wanted to drop as data-loss changes. Rather than risk dropping real data, DDL was applied directly using the `pg` Node.js client. This is safe because the new objects (tables, enum, column) are additive only.
- **guardianId as integer (not FK):** Follows the same pattern as the existing `absences` table — `guardian_id` stores `auth.id` from JWT, no foreign key to the `profile` table. This is the established pattern in this codebase.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] Used direct pg DDL instead of drizzle-kit push**
