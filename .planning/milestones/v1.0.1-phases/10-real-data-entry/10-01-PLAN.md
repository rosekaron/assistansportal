## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| guardian (human) → Claude | Real PII (pno, names, address, bank numbers) supplied inline; Claude must route these to Postgres without persisting them to git |
| Claude → Express (localhost) | JWT-signed PUT body crosses process boundary; body contains PII |
| Express → Postgres | Whitelist (profile.ts:20–46) already in place from Phase 7 D-19 |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-10-01 | I (Info Disclosure) | PLAN.md / commit msgs / terminal scrollback | mitigate | Action uses `{guardian-supplied at runtime}` placeholders, never real values. Commit messages mention field NAMES only (e.g. "populated address_street") not VALUES. |
| T-10-02 | I (Info Disclosure) | JWT_SECRET in .env | mitigate | Reuse the JWT forge pattern from 09-UAT.md (read $JWT_SECRET from .env, sign in-memory, never echo to logs or files). `set +x` before any shell block that handles the secret. |
| T-10-03 | T (Tampering) | profile PUT body field typos | mitigate | Issue GET /api/profile AFTER the PUT and diff response against the set of keys sent; abort if any target field is still empty / placeholder. |
| T-10-04 | D (Denial/data-loss) | overwriting guardianName or guardianEmail with empty strings | mitigate | Before the PUT, GET current profile and carry forward every guardian_* and patient_* value not intentionally being changed (PUT is a full-update, not PATCH — missing fields go to "" per whitelist defaults). |
| T-10-05 | R (Repudiation) | no audit trail for PII write | accept | Single-tenant dev app; Postgres `profile.updatedAt` auto-set. Full audit logging deferred (v2.0 multi-tenant). |
