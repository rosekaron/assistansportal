# Phase 3.5 Plan 06: Monthly Page — Reports + Payroll + FK Stepper

**One-liner:** Consolidated Monthly.tsx page merging Reports and Payroll into a 3-step sequential stepper with FK form download gate.

---

## What Was Built

### Monthly.tsx (871 lines)

A new page that replaces the two separate Reports and Payroll pages with a single compliance workflow page. The guardian completes the monthly cycle without navigating between pages.

**3-step progress stepper:**
- Step 1 — Daily reports: per-assistant summary chips showing hours progress, report table with approve/reject per entry and Approve all button, Verified/Manual badge per entry
- Step 2 — Payroll: 3 stat chips (total gross pay, total employer cost, outstanding), per-assistant AssistantPayrollCard with inline payment recording
- Step 3 — FK forms: FK 3059 per-assistant + FK 3057 full-month, disabled with tooltip until steps 1 and 2 are both complete

**Verified badge implementation:** Uses `entry.verified === true` (canonical DB column set by clock-out in Plan 02). Does NOT use the `source === "self_book"` heuristic.

**Single shared month state:** One `year`/`month` state drives the `monthKey` used for both `entriesApi.list()` and `payrollApi.list()` queries. Month navigator (ChevronLeft/ChevronRight with aria-labels) + month input control.

**FK gate logic:**
- `step1Complete = monthPendingCount === 0 && entries.length > 0`
- `step2Complete = payrollRecords.every(r => r.status === "approved")`
- `fkUnlocked = step1Complete && step2Complete`
- Server independently validates entry approval status on PDF generation (T-3.5-17)

**Removed from Reports.tsx (cost tracking — post-MVP per UI-SPEC):**
- No `costsApi`, `ratesApi` imports
- No `COST_LABELS`, `COST_COLORS`, `showAddCost`, `costForm`, `monthCosts`
- No `addCost`, `deleteCost` mutations
- No FK reimbursement comparison section
- No `ratesError` banner

### App.tsx

- Added `import MonthlyPage from "@/pages/Monthly"`
- Replaced stub `<Route path="/monthly" element={<Dashboard />} />` with `<Route path="/monthly" element={<MonthlyPage />} />`
- Legacy redirects preserved: `/reports → /monthly`, `/payroll → /monthly`, `/compliance → /monthly`
