# Phase 2.5: UI Overhaul & Design System - Context

**Gathered:** 2026-04-07
**Status:** Ready for planning

<domain>
## Phase Boundary

Fix the broken Tailwind CSS build (utility classes not generating) and rebuild the visual design
system to a B2B-ready, care.com-inspired professional standard. Covers both guardian and assistant
views. Does NOT include new features — layout, typography, color, spacing, and component polish only.

This phase exists because:
1. Tailwind utility classes are not rendering (only 51 base rules in the browser — flex, colors,
   shadows all missing). The app appears unstyled.
2. The design needs to match a professional healthcare B2B product standard suitable for sale
   to large care organisations (Humana, Attendo) and European market expansion.

</domain>

<decisions>
## Implementation Decisions

### D-01: Tailwind CSS Fix (Blocker — Must Be First)
- Only 51 CSS rules are being generated (Tailwind base only, zero utilities)
- Root cause: content scanning is not finding source files in JIT mode
- Fix options to investigate: postcss.config.js vs inline vite.config.ts conflict; ESM vs CJS
  tailwind.config.js loading; content path resolution when invoked with explicit config path
- Must be resolved before any visual work begins — current screenshots are misleading

### D-02: Design Direction
- Reference: care.com — clean, professional, accessible, trust-inspiring healthcare aesthetic
- NOT developer-tool dark mode; NOT dense spreadsheet UI
- Color direction: defer until Tailwind fix is confirmed working and we can see the real render
- Principle: works for a self-managing guardian today AND feels enterprise-grade for B2B demo

### D-03: Target Audiences (Design Must Serve Both)
- **Current:** Self-managing guardians handling their own assistansersättning (minimal feature set)
- **Near-term B2B:** Care organisations like Humana and Attendo (Sweden) — need professional dashboard feel
- **Future:** European expansion — Norway, Finland, Denmark, Netherlands (similar regulatory framework)
- Design must NOT feel like a personal hobby project — it must feel like a product a care org would trust

### D-04: Guardian Layout & Nav
- Full guardian layout and sidebar needs redesign
- Nav items, active states, logo treatment, weekly hours widget — all in scope
- Page-level layout (header, content area, card grid) — in scope
- Keep the same routes and page structure — only visual layer changes

### D-05: Assistant Dashboard
- Weekly strip, tab navigation, shift cards — all need redesign
- Current design is structurally sound but visually underdone
- Same data, better presentation

### D-06: Component Consistency
- Cards, badges, buttons, dialogs, form controls — align to a consistent visual language
- Typography scale, spacing rhythm, color token usage — must be consistent across all pages
- The existing Tailwind token system (CSS variables in index.css) is the right foundation — keep it

### Claude's Discretion
- Exact color palette values (after seeing real render post-fix)
- Typography scale adjustments
- Card shadow depths and border treatments
- Specific animation/transition choices
- Whether to add a dark mode toggle (probably defer to v2)

</decisions>

<code_context>
## Existing Code Insights

### Reusable Assets
- CSS variable token system in `index.css` — `--primary`, `--background`, `--card`, `--muted`, etc. — keep these, fix the rendering
- Radix UI primitives (Dialog, Select, Tabs, Switch) — keep all, just restyle wrappers
- `AssistantAvatar` color-coded initials component — keep, works well
- `PageHeader` with title/description/action slot — keep pattern, may adjust spacing

### The Core Bug
- `document.styleSheets[0]` has 51 rules (base only) — `.flex`, `.bg-primary`, `.text-sm` are absent
- `tailwindcss` PostCSS plugin is being invoked via `vite.config.ts` with explicit config path
- AND `postcss.config.js` exists with `{ tailwindcss: {}, autoprefixer: {} }`
- When both exist, Vite uses the inline config and ignores the file — this is fine
- Likely issue: content paths `["./index.html", "./src/**/*.{ts,tsx}"]` aren't resolving from CWD
  when the inline PostCSS is active — needs investigation with actual file path logging

### Established Patterns (Do Not Break)
- Zustand auth store (`localStorage.auth` Zustand persist format — NOT raw `token` key)
- React Query for all data fetching
- `requireGuardian` / `requireAssistant` middleware on all routes
- `absenceApi`, `entriesApi`, `costsApi` namespace pattern in `api.ts`

### Integration Points
- `client/src/App.tsx` — routing (guardian vs assistant split) — do not change route structure
- All page components receive data via React Query — design changes are pure UI layer

</code_context>
