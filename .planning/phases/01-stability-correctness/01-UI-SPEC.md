## Interaction Contracts

### STAB-03: Rate Loading (only API-adjacent UI change)

The client's `Reports.tsx` currently reads hardcoded constants. After the fix, it must fetch rates
from `/api/rates` on component mount.

| State | Visual | Behaviour |
|-------|--------|-----------|
| Loading | Existing spinner or skeleton — match current Reports.tsx loading pattern | Non-blocking; use React Query `isLoading` state already in use on page |
| Loaded | Rates render as before; no visible change to the user | Display `fkHourlyRate` and `employerTaxRate` from API response |
| Error | Inline muted text: "Unable to load rate configuration. Default rates are being used." | Fall back to `FK_HOURLY_RATE=334` and `EMPLOYER_TAX_RATE=0.3142` defaults; no toast or modal |

No new loading spinners, modals, or toasts may be introduced for this change. The error fallback
is inline text only, styled with `text-sm text-muted-foreground`.

### STAB-04: camelCase Refactor

No visible interaction change. TypeScript field name corrections (`req_status` → `reqStatus`, etc.)
must produce identical rendered output. If any data was silently undefined due to the snake_case
bug, it will now render — executor must verify no layout shifts occur in `Hours.tsx`.
