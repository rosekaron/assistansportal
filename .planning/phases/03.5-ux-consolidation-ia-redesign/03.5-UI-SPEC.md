## Per-Page Layout Contract

### /home — Home

**Primary goal:** One glance answers "who's working this week?" and "what needs my attention this month?"

**Focal point:** GCal schedule view is first — it's what the guardian comes to check. Pending actions are below.

**Sections (top to bottom):**
1. PageHeader: greeting + date + care recipient name
2. **This week's schedule** — read-only GCal sync view
   - 7-day column layout (Mon–Sun), compact rows
   - Each day: assistant name + shift hours (pulled from GCal)
   - "Mark absent" quick action per day slot (rare — tap day → confirm absence type)
   - GCal connection status: if not connected → inline banner "Connect Google Calendar in Settings →"
3. **Pending actions** — what needs attention this month
   - Daily reports pending: "{N} reports to approve" → links to /monthly
   - Payroll pending: "{N} payroll records to approve" → links to /monthly
   - FK deadline: days until submission deadline
   - FK download: available only when all reports + payroll approved
4. Setup banner (conditional, keep existing — shown until setup complete)

**FK download gate:** disabled + tooltip "Approve all reports and payroll first" until both are complete.

**Empty state (all clear):** "All caught up — nothing pending" with CheckCircle2 icon.

**Leave recording:** "Mark absent" on a shift slot opens a minimal dialog: absence type (Sick / VAB / Holiday / Other) + date range. No dedicated page.

---

### /monthly — Monthly

**Primary goal:** Complete the monthly compliance checklist in order — approve reports, approve payroll, download FK forms.

**Sections (top to bottom):**
1. PageHeader: "Monthly" + month selector
   - ChevronLeft: `aria-label="Previous month"`
   - ChevronRight: `aria-label="Next month"`
2. **Progress stepper** (3 steps, visual):
   - Step 1: Daily reports — {approved}/{total}
   - Step 2: Payroll — {approved}/{total}
   - Step 3: FK forms — unlocked when steps 1 + 2 complete
3. **Daily reports section**
   - Per-assistant summary chips (approved, pending, total hours)
   - Report table: assistant, date, hours, status, approve/reject
   - "Approve all" button per assistant
4. **Payroll section**
   - 3 stat chips: total gross pay · total employer cost · total outstanding
   - Per-assistant payroll cards (billable hours, absence breakdown, gross, tax, total)
   - Approve button per card; payment recording inline
   - "Generate payroll" when no records exist
5. **FK forms section** (locked until steps 1 + 2 complete)
   - "Download FK 3059" + "Download FK 3057" buttons
   - Disabled with tooltip "Approve all reports and payroll first" when incomplete

**Empty state:** "Nothing yet for {month}. Reports appear here once assistants submit them."

---

### /records — Records

**Primary goal:** Look up anything from the past — payroll, FK submissions, leave.

**Read-only. No actions.**

**Sections:**
1. PageHeader: "Records" + year filter
2. **Tab bar:** Payroll | FK Submissions | Leave

**Payroll tab:**
- Month selector
- Per-assistant rows: month, assistant, gross pay, status, total cost
- Expandable to show full card detail

**FK Submissions tab:**
- List of months: month, date downloaded, form type (3057 / 3059)
- Read-only — downloads happen on /monthly

**Leave tab:**
- Filter by assistant + year
- VAB balance per assistant (remaining of 120 days)
- Sick days YTD per assistant
- Full absence history: date range, type, days

**Empty state:** "No records yet. Data appears here once you complete a monthly cycle."

---

### /settings — Settings

**Primary goal:** Manage assistants, configure account details, FK settings, and integrations.

**Sections (top to bottom):**
1. PageHeader: "Settings"
2. **Assistants** ← moved from standalone /assistants page
   - Weekly hours budget bar
   - Active assistants grid (3 col): name, email, personnummer, phone, hours/week, flex flag
   - "View leave →" link per card (links to /records > Leave tab)
   - Pending invites table (conditional)
   - "Add assistant" button
   - "How invitations work" explainer
3. **Integrations**
   - Google Calendar: connect/disconnect + sync status
   - Setup guide: static 3-step card (connect → shifts visible on Home → assistants auto-matched)
4. **Scheduling**
   - Self-book toggle, approval mode, booking window
5. **Account**
   - Guardian profile (left) + Care recipient + FK details (right)

**Destructive:** Remove assistant → Dialog confirm (keep existing pattern).

## Assistant View — V1 Design

The assistant view (`/assistant` route, `AssistantDashboard.tsx`) is redesigned around two V1 requirements: **clock-in/out** (verified presence) and **multi-family support** (one assistant, many guardian families).

### Removed features (product decisions)

| Feature | Decision | Reason |
|---------|----------|--------|
| Proposals tab (accept/decline shifts) | **Removed** | Scheduling happens offline — face to face, WhatsApp, phone. No in-app proposal flow needed. |
| Open slots tab (self-book available shifts) | **Removed** | Same reason. Guardian doesn't create slots in-app; shifts are agreed offline. |
| Leave requests from assistant side | **Not added** | Guardian marks absence for payroll/reporting purposes. Assistant communicates via other channels. |
| Manual report submission | **Replaced** | Clock-in/out timestamps auto-create the verified report; no separate submit form needed. |

---

### Clock-in / Clock-out (V1)

**Why this matters:** Personal assistance has an endemic trust problem. Guardians and care agencies need verified evidence of presence. Clock-in/out provides a timestamped, device-bound record that anchors the shift report to actual attendance.

**Hero element:** The clock-in/out button is the first and largest element on the assistant dashboard — it replaces the manual report submission flow entirely.

**State machine:**

```
Clocked out → [Clock in] → Clocked in (timer running) → [Clock out] → Report auto-created
```

**Layout:**

```
┌─────────────────────────────────┐
│  Family selector (if multi)     │
│  ← Larsson family               │
├─────────────────────────────────┤
│  CLOCKED OUT                    │
│  ┌───────────────────────────┐  │
│  │   Clock in                │  │  ← large primary button, full-width
│  └───────────────────────────┘  │
│  Last shift: yesterday, 8h      │
├─────────────────────────────────┤
│  Today's shift (from GCal)      │
│  09:00–17:00 · Larsson family   │
└─────────────────────────────────┘
```

**When clocked in:**

```
┌─────────────────────────────────┐
│  CLOCKED IN                     │
│  Started: 09:04                 │
│  Duration: 2h 31m (live timer)  │
│  ┌───────────────────────────┐  │
│  │   Clock out               │  │  ← destructive-styled, requires confirm
│  └───────────────────────────┘  │
└─────────────────────────────────┘
```

**On clock-out:**
- Confirmation dialog: "End shift? {start time} – {end time} = {duration}. This will create a shift report." + Confirm / Cancel
- Auto-creates a shift report entry linked to the guardian and month
- Report is tagged `verified: true` (distinguishes from legacy manual entries)

**Verification approach (V1):** Device-bound timestamp only (server records IP + user-agent). Biometric and GPS are post-MVP.

**Guardian visibility:** Monthly page shows `Verified` badge on clock-in-sourced reports vs `Manual` badge on older entries. Approval flow is identical — guardian still approves all reports.

---

### Multi-family support (V1)

**Why this matters:** Assistants are a primary acquisition channel — families join because their assistant is already on the platform. An assistant who works for two or three families must be able to clock in/out for each without confusion.

**Model:** One assistant account → linked to N guardian families via `assistantGuardianLinks` table (assistant_id, guardian_id, active). Each clock-in record is tagged with a guardian_id.

**Family selector:**
- Shown at the top of the assistant dashboard when the assistant has ≥ 2 active families
- Persistent selection (stored in sessionStorage) — does not reset on each visit
- All views (clock-in state, upcoming shifts, reports) filter to the selected family
- "Switch family" is always reachable from the header

**Assistant dashboard after V1 redesign — structure:**

```
Header: assistant name + family selector (if multi-family)
─────────────────────────────────────────
Clock-in/out hero section
  • Current state (clocked in / out)
  • Large action button
  • Live timer (when clocked in)
  • Last shift summary (when clocked out)
─────────────────────────────────────────
Today's scheduled shift (GCal, read-only)
─────────────────────────────────────────
Tabs: Upcoming | Reports
  Upcoming: next 7 days of shifts (for selected family)
  Reports: auto-generated entries from clock-out records
           + any unverified legacy entries needing review
─────────────────────────────────────────
```

**Reports tab (revised):** No manual submission form. Shows a list of auto-created reports from clock-out events. Each row: date, hours (clock-in to clock-out), family, status (Pending approval / Approved). Read-only — guardian approves on Monthly page.
