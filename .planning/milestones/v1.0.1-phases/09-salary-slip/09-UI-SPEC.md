# Phase 9 — UI Design Contract

> Visual and interaction contract for Salary Slip (Anhörig Model). Generated by gsd-ui-researcher from REQUIREMENTS.md (SLIP-01..07), CONTEXT.md (14 locked decisions D-01..D-14 + Claude's discretion items), and codebase scout of `client/tailwind.config.js`, `client/src/index.css`, `client/src/pages/Monthly.tsx`, `client/src/pages/AssistantDashboard.tsx`, `client/src/pages/Settings.tsx`, and `client/src/components/ui/*`. Phase 7 UI-SPEC is the visual-language baseline; Phase 9 extends it, introduces zero new tokens.

**Scope of this contract:** Three runtime UI surfaces + one non-runtime PDF layout.

1. `Monthly.tsx` — per-approved-assistant "Ladda ner lönespecifikation" button on the AGI (4805) row / new Lönespec row (SLIP-01, D-13).
2. `AssistantDashboard.tsx` — new "Lönespecifikationer" section with slip list + per-row download (SLIP-02, D-13).
3. `Settings.tsx → Assistants edit dialog` — three new fields in the Anställning & ekonomi section (salary_model, hourly_rate_override, payment_method) + one new field on Settings → Profile (default_pay_day) (SLIP-06, D-13).
4. Server-rendered `lonespec-{YYYY-MM}-{assistant}.pdf` — A4 plain-text layout per ROADMAP §198–228 mock (D-01, D-02).

**Out of scope:** All items enumerated in CONTEXT.md §domain "Out of scope" — Fremia/Custom live logic, skattetabell display, banking-day shift, per-month pay-date override, PDF blob persistence, roles, real-data entry.

## Interaction Contract

### Monthly.tsx Lönespec button states

1. **Enabled (payroll approved + rate set):** `variant="default"` (primary blue), `Download` icon + label `Ladda ner lönespec`, tooltip `Ladda ner lönespecifikation (PDF)`. Click → `POST /api/pdf/lonespec` → server streams PDF blob → client triggers browser download via anchor-with-`download`-attribute trick (mirrors `Monthly.tsx:627–630` exactly).
2. **Disabled (payroll not approved):** `variant="outline"`, `disabled`, `cursor-not-allowed`, label `Lönekörning ej godkänd`, tooltip `Godkänn lönekörning först för att ladda ner lönespecifikationen.` Same pattern as existing 4805 button at `Monthly.tsx:1119–1123`.
3. **Disabled (rate NULL):** `variant="outline"`, `disabled`, `cursor-not-allowed`, label `Timlön saknas`, tooltip `Sätt timlön i Inställningar → Assistenter`. Click handler never fires.
4. **Loading (during generation):** replace label text with `Genererar...` + small inline spinner (reuse lucide `Loader2` `animate-spin` convention already used by save buttons in Settings). Button stays `variant="default"` but `disabled` during the fetch to prevent double-clicks.
5. **Error (post-generation):** inline `text-sm text-destructive` below the button row for 4 seconds showing the mapped error copy above, then auto-dismiss. Consistent with the existing error pattern at `Monthly.tsx:631` (currently an `alert()` — Phase 9 prefers inline toast/text to match the rest of the app's current direction; alert() is acceptable fallback if executor deems inline-toast out-of-scope).

### AssistantDashboard Lönespecifikationer section states

1. **Loading (initial fetch):** skeleton row × 3 (reuse existing skeleton pattern if present, else `bg-muted animate-pulse h-14 rounded-md`).
2. **Populated:** vertical list of slip rows, newest first. Each row: month-year (left, `text-sm font-medium`), below it metadata line (`text-xs text-muted-foreground`: doc number · issuedAt), download button (right, `variant="outline"`, `Download` icon + `Ladda ner`).
3. **Empty:** centered `FileText` icon (32px, `text-muted-foreground`) + heading + body copy per Copywriting.
4. **Error (fetch failed):** centered `text-sm text-destructive` with error copy, no retry button (page reload suffices; parity with existing AssistantDashboard error handling).
5. **Click download:** `GET /api/pdf/lonespec/me?month=YYYY-MM` → stream to download via same anchor trick. The `/me` endpoint scopes to JWT — cross-assistant access returns 403 (SLIP-02 gate). Client does not need to check ownership — server is the gate.

### Settings dialog additions

1. **Salary-model Select:** 3 options; `Fremia` and `Custom` are `disabled` at the Radix SelectItem level (`disabled={true}` prop). Attempting keyboard navigation to them skips per Radix convention. Selected value is always `anhörig` in v1.0.1.
2. **Hourly-rate-override Input:** numeric input accepting decimal (step 0.01). Empty string persists as NULL in database. Browser-native `:invalid` styling for values outside `min="0"` (no negative rates). No custom validation UI — matches Phase 7 D-18 client-validation-only stance.
3. **Payment-method Select:** default `Bankgiro`. All three options enabled. Persists to `assistants.payment_method`.
4. **Save action:** Phase 9 adds no new save button — reuses the existing Phase 7 `Spara ändringar` CTA that already posts the full dialog state through `PUT /api/assistants/:id`. Route whitelist extends to include `salary_model`, `hourly_rate_override`, `payment_method` (covered by CONTEXT D-07 + Phase 7 D-19 pattern).

## Accessibility

- Every new `<Input>` and `<Select>` has an associated `<Label>` via the existing primitive wiring; `htmlFor` / `id` inherited.
- Disabled Select options announce as `aria-disabled="true"` via Radix default; screen readers skip them.
- Download buttons have `aria-label` when icon-only would be ambiguous; Phase 9's buttons always include visible Swedish label text, so no extra aria-label needed.
- Tooltip content on disabled buttons is announced via `aria-describedby` wired by Radix Tooltip primitive.
- Focus-visible outline 2px solid `hsl(var(--ring))` with 2px offset (inherited from `index.css:73`).
- Swedish labels language-tagged via existing `<html lang="sv">` root attribute — no per-field `lang` override.
- Color contrast: error `--destructive` (`0 65% 48%`) on `--background` (`210 20% 98%`) ≈ 5.3:1, passes WCAG AA. Muted helper text (`--muted-foreground` = `220 12% 46%`) on `--background` ≈ 4.7:1, passes AA for body text.
- Touch targets: download buttons at minimum 40px tall via Button primitive default (`h-10 px-4`). Slip list rows are non-interactive (row metadata is display-only); the Download button is the touch target, padded with `py-3.5` outer row padding for comfortable adjacent tap zones.

**PDF accessibility:** Out of scope for v1.0.1. PDF is rendered by pdfkit without tagged-PDF structure; screen-reader accessibility of the output is not a v1.0.1 requirement. Captured as forward-deferred if a future compliance pass demands PDF/UA.
