<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → Express | All HTTP requests cross this boundary. The new SPA catch-all returns `index.html` for any unmatched GET; sensitive routes (auth, pdf, payroll) are registered above and remain unaffected. |
| dev process → production process | The `NODE_ENV === "production"` guard is the boundary. Misconfiguring NODE_ENV in dev would not enable the static block (current dev sets NODE_ENV=development or leaves it unset). |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-11-07 | Tampering / Information disclosure | SPA catch-all `app.get("*")` could intercept unmatched `/api/*` requests and return `index.html` (200) instead of 404, masking routing bugs and leaking SPA HTML to API clients | mitigate | Task 2 places the block AFTER all `app.use("/api/...")` registrations and AFTER `app.get("/api/health")`. Acceptance criterion `awk` check enforces ordering. |
| T-11-08 | Elevation of privilege | Production static block runs in dev if NODE_ENV is accidentally set to "production" | accept | The guard itself is the mitigation; misconfiguring NODE_ENV is a deployment concern handled in Phase 12 (env var checklist). Cost of accident in dev is low: just serves stale client/dist if it exists. |
| T-11-09 | Denial of service | `express.static` could serve large files outside `client/dist` if path is mis-resolved | mitigate | `path.join(__dirname, "../../client/dist")` is a fixed absolute resolution; no user-controlled segments. express.static is sandboxed to the directory passed in. |
</threat_model>
