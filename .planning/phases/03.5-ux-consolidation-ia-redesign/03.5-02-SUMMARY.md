# Phase 03.5 Plan 02: Clock-In/Out API Summary

**One-liner:** Clock-in/out API with assistantGuardianLinks fraud gate, auto-verified shift report creation on clock-out, and server-side assistantId resolution from JWT.

## What Was Built

Three Express routes mounted at `/api/clock`, all guarded by `requireAuth + requireAssistant`:

| Endpoint | Method | Purpose |
|----------|--------|---------|
| `/api/clock/in` | POST | Records assistant arrival; creates `clockEvents` row with `clockType="in"`, `verified=false` |
| `/api/clock/out` | POST | Records departure; marks clock-in event `verified=true`; auto-creates `entries` row with `verified=true` |
| `/api/clock/status` | GET | Returns `{ state: "clocked_in" \| "clocked_out", activeEvent? }` |

### Security Properties (Threat Model Mitigations)

| Threat | Mitigation |
|--------|-----------|
| T-3.5-04 Spoofing assistantId | `getAssistantId(req.userId)` resolves server-side from JWT — body field ignored |
| T-3.5-05 Fraudulent clock-in for unlinked family | Both `/in` and `/out` query `assistantGuardianLinks` for `(assistantId, guardianId, active=true)` → 403 if absent |
| T-3.5-06 Guardian calling assistant endpoints | `requireAssistant` middleware rejects `role !== "assistant"` with 403 |

### Clock-Out Auto-Entry

On `/api/clock/out`:
1. Finds the most recent unverified clock-in event (`clockType="in"`, `verified=false`)
2. Sets that event's `verified=true` (consumed)
3. Inserts `clockEvents` row (`clockType="out"`, `verified=true`)
4. Inserts `entries` row: `verified=true`, `reqStatus="approved"`, `repStatus="pending"`, `source="self_book"`

The `entries.verified=true` flag is the canonical "Verified" badge trigger read by Plan 06 on the guardian's Monthly page.
