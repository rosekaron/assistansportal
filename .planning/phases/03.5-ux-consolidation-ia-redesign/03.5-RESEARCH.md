**Researched:** 2026-04-11

## Summary

This phase is a pure frontend refactor. No server routes change, no database schema changes. Every
change is isolated to `client/src/` — specifically `App.tsx`, `Layout.tsx`, and the page files.
The design system (colors, typography, tokens, custom components) is already established and is
NOT modified.

The primary work falls into six categories: (1) route renames with redirect handling, (2) the
`/hours` route removal and feature relocation, (3) the Calendar wizard extraction to Settings, (4)
the Reports cost-tracking section removal, (5) the Dashboard FK download gate addition, and (6) the
Payroll summary stat row addition. Each of these is fully mechanical — no new APIs, no new
components from registries.

The UI-SPEC in `03.5-UI-SPEC.md` is the locked design contract for this phase. Research findings
below are grounded in reading the actual current source files.

**Primary recommendation:** Organize work into 6 discrete waves, one per change category. Each
wave is independently verifiable. Keep every change client-side only; do not touch `server/`.

### Change 6: Payroll Summary Stat Row

**Current Payroll.tsx (VERIFIED by reading full file):**
The page renders:
1. `PageHeader` with month selector
2. Loading skeletons OR empty state OR `records.map(AssistantPayrollCard)`

There are no summary stat chips currently. The per-card stats are: billable hours, absence hours,
gross pay, employer tax, total cost.

**New stat row (from UI-SPEC):** 3 chips showing totals across all records for the selected month:
- "Total bruttolön: {sum} kr" (sum of `record.grossPay`)
- "Total arbetsgivaravgift: {sum} kr" (sum of `record.employerContributions`)
- "Utestående: {sum} kr" (sum of outstanding balance per record — requires either querying
  payments or computing from records)

**Outstanding balance complexity:** The per-card outstanding is `record.grossPay - totalPaid`.
The `totalPaid` per record requires a payments query (`["payments", record.id]`). At the page
level, computing total outstanding across all records requires either:
  (a) Summing `record.grossPay` and subtracting total of all payments across all records (requires
      N payment queries at the page level), OR
  (b) Simplifying to "total gross pay not yet marked approved" (i.e., sum grossPay where status ===
      "draft"), which approximates outstanding without payment queries.

Per the UI-SPEC: "These are calculated client-side from the records array. No new API needed."
This strongly implies option (b) — deriving outstanding from record data only, not payment data.
[CITED: 03.5-UI-SPEC.md § /payroll — Lön]

**Implementation:** When records exist, render above the cards:
```tsx
{records && records.length > 0 && (
  <div className="grid grid-cols-3 gap-4 mb-6">
    {[
      { label: "Total bruttolön", value: records.reduce((s, r) => s + r.grossPay, 0) },
      { label: "Total arbetsgivaravgift", value: records.reduce((s, r) => s + r.employerContributions, 0) },
      { label: "Utestående", value: records.filter(r => r.status === "draft").reduce((s, r) => s + r.grossPay, 0) },
    ].map(({ label, value }) => (
      <div key={label} className="bg-secondary rounded-xl px-4 py-3 border border-border">
        <p className="text-xs font-semibold uppercase tracking-wide text-muted-foreground mb-1">{label}</p>
        <p className="text-xl font-semibold font-mono tabular-nums">{formatSek(value)}</p>
      </div>
    ))}
  </div>
)}
```
This uses the already-imported `formatSek` helper in Payroll.tsx.

## Common Pitfalls

### Pitfall 1: Stale `window.history.replaceState` in Calendar.tsx

**What goes wrong:** Calendar.tsx line 103 runs `window.history.replaceState({}, "", "/calendar")`
on mount if the URL has `?gcal_connected=true`. After renaming to `/schedule`, this will push the
old `/calendar` URL into history — the nav active state will be wrong.
**How to avoid:** Update this string to `"/schedule"` when renaming the file.
**Warning signs:** After OAuth callback, active nav item shows wrong highlight.

### Pitfall 2: Forgetting the FileText → FileCheck Icon Swap

**What goes wrong:** Layout.tsx imports `FileText` (line 6) for the current Reports nav item.
The new Compliance item uses `FileCheck`. If the import is not updated, you get a runtime error
or the wrong icon.
**How to avoid:** Update the import on line 6 of Layout.tsx — remove `FileText`, add `FileCheck`.
**Warning signs:** TypeScript error `FileText is declared but never used` after swap.

### Pitfall 3: costsApi Import Still in Compliance.tsx

**What goes wrong:** Reports.tsx imports `costsApi` and `ratesApi`. If the file is copied to
Compliance.tsx and cost tracking is removed from JSX but the imports/state remain, TypeScript will
emit unused variable warnings (or silent bugs if cost state is partially left in).
**How to avoid:** Do a clean rewrite of the component top-section, not just JSX deletion. Remove
all cost-related state, queries, and computed values.
**Warning signs:** `costsApi` import present in Compliance.tsx with no usages.

### Pitfall 4: Dashboard navigate("/reports") not Updated

**What goes wrong:** Dashboard.tsx line 230 calls `navigate("/reports")`. After the route rename,
this navigates to a 404 (or the wildcard catch-all `/login` redirect per App.tsx line 91).
**How to avoid:** Update Dashboard.tsx line 230 to `navigate("/compliance")` in the same change
wave as the route rename.
**Warning signs:** Clicking "reports to approve" in the Needs Attention card shows login page.

### Pitfall 5: AssistantAbsenceSummary Leaves a Stale Query

**What goes wrong:** If the `<AssistantAbsenceSummary>` render is removed but the `absenceApi`
import is left in Assistants.tsx, no error occurs at runtime but the import is dead code. More
importantly, if the query cache still contains stale balance data from previous renders, the
Leave page may show data that was previously fetched but not refreshed.
**How to avoid:** Remove `absenceApi` and `AbsenceBalance` imports together with the component.
The Leave page has its own `absenceApi.balance()` queries per assistant — they're independent.
**Warning signs:** TypeScript "declared but never read" warning on `absenceApi`.

### Pitfall 6: Payroll Stat Row Shows During Loading State

**What goes wrong:** If the stat row is rendered before the payroll query resolves, the sums will
be 0/NaN, showing "0 kr" chips before the skeleton disappears.
**How to avoid:** Render the stat row inside the `!isLoading && records && records.length > 0`
branch — the same branch that renders the per-assistant cards.
**Warning signs:** Flickering "0 kr" chips on page load.
