# Phase 03.5 Plan 08: Settings Assistants Embed and GCal Guide Summary

**One-liner:** Embedded full Assistants management into Settings.tsx with weekly budget bar, assistant cards with "View leave" link to /records, and static 3-step GCal setup guide card.

## What Was Built

Settings.tsx was restructured to embed the Assistants management section (previously in Assistants.tsx) and gain a static GCal setup guide. The page now has four sections in UI-SPEC order:

1. **Assistants** — weekly hours budget bar, active assistants grid (3-col), "View leave" link per card, pending invites table, Add assistant dialog, Edit assistant dialog, Remove confirm dialog
2. **Integrations** — existing GCal connect/disconnect UI plus a new collapsible 3-step setup guide (wizardOpen toggle, no API calls)
3. **Scheduling** — existing self-book toggle and options (unchanged)
4. **Account** — existing guardian profile, care recipient, FK details (unchanged)

## Deviations from Plan

None — plan executed exactly as written. The `absenceApi` and `AssistantAbsenceSummary` component were fully removed and replaced with the "View leave" link to `/records`.

## Known Stubs

None — all data is wired to existing API queries (assistantsApi, invitesApi, profileApi, settingsApi). The GCal setup guide is intentionally static (purely informational per RESEARCH.md Change 8).

## Threat Surface Scan

No new network endpoints or auth paths introduced. All mutations (remove assistant, create invite, revoke invite) use existing API routes with server-side guardian ownership validation. The removal of absenceApi queries from Settings reduces surface area (T-3.5-21 accepted).
