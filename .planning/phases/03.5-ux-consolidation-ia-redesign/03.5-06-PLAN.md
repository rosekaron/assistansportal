Create Monthly.tsx as a new file. This page consolidates Reports + Payroll logic into one
component with a progress stepper.

**Structure:**

1. Copy ALL utility functions from Payroll.tsx (formatSek, formatHours, formatAbsenceBreakdown,
   monthLabel, prevMonth, nextMonth, currentMonth) and the `pad` function from Reports.tsx.

2. Copy the AssistantPayrollCard component from Payroll.tsx unchanged. It is self-contained
   and handles all payment inline mutations.

3. Component state:
   ```
   const [year, setYear] = useState(now.getFullYear());
   const [month, setMonth] = useState(now.getMonth());  // 0-indexed like Reports.tsx
   const monthKey = `${year}-${pad(month + 1)}`;  // used for both reports and payroll queries
   ```

4. Queries:
   - profileApi.get()
   - assistantsApi.list()
   - entriesApi.list({ start, end }) for the month
   - payrollApi.list(monthKey)
   - No costsApi, ratesApi queries

5. Mutations:
   - approveEntry (entriesApi.update({ id, repStatus: "approved" }))
   - rejectEntry (entriesApi.update({ id, repStatus: "rejected" }))
   - approvePayroll (payrollApi.approve(recordId))
   - generatePayroll (payrollApi.generate(monthKey))
   - fk3057Download (pdfApi.fk3057)
   - fk3059Download (pdfApi.fk3059)
   - No addCost, deleteCost mutations

6. Computed values:
   - summaries: per-assistant { approved, pending, total, hours } from entries
   - monthPendingCount = entries where repStatus === "pending"
   - step1Complete = monthPendingCount === 0 && entries.length > 0
   - step2Complete = payrollRecords.length > 0 && payrollRecords.every(r => r.status === "approved")
   - fkUnlocked = step1Complete && step2Complete
   - payrollApprovedCount, payrollTotalCount for stepper display
   - totalGross = payrollRecords.reduce((s, r) => s + r.grossPay, 0)
   - totalEmployerCost = payrollRecords.reduce((s, r) => s + r.employerContributions, 0)
   - outstanding = payrollRecords.filter(r => r.status === "draft").reduce((s, r) => s + r.grossPay, 0)

7. Layout:
   ```
   PageHeader: "Monthly" + month selector (ChevronLeft/ChevronRight with aria-labels)

   Progress Stepper (3 steps, horizontal):
     [1] Daily reports — {approved}/{total}  [—]  [2] Payroll — {approved}/{total}  [—]  [3] FK forms
     Complete = filled circle, active = outlined, locked = gray
     Stepper is purely visual, does NOT scroll to sections — all sections always visible

   Section 1 — Daily reports:
     Per-assistant summary chips (same as Reports.tsx summaries section)
     Report table per assistant with approve/reject buttons and Verified/Manual badge
     "Approve all" button per assistant
     Empty: "Nothing yet for {monthLabel}. Reports appear here once assistants submit them."

   Section 2 — Payroll:
     3 stat chips (Total gross pay / Total employer cost / Outstanding)
     Only when !isLoading && payrollRecords.length > 0
     Per-assistant AssistantPayrollCard components
     "Generate payroll" button when payrollRecords.length === 0 (and month has entries)

   Section 3 — FK forms:
     Background: bg-muted/50 when locked (fkUnlocked === false)
     "Download FK 3059" button — per-assistant, same as Reports.tsx
     "Download FK 3057" button — one for the month
     Both disabled with title="Approve all reports and payroll first" when !fkUnlocked
   ```

8. Verified/Manual badge implementation:
   Use the canonical `entry.verified` boolean column (added in Plan 01 schema, set to true
   by Plan 02 clock-out). Do NOT use the source === "self_book" heuristic.
   For each entry row, show badge:
   - entry.verified === true  → Badge variant="success" text="Verified"
   - entry.verified === false → Badge variant="secondary" text="Manual" (only on entries, not proposals)

DO NOT include: costsApi, ratesApi, COST_LABELS, COST_COLORS, showAddCost, costForm, monthCosts,
addCost, deleteCost, ratesError banner, totalCosts, costsByCategory, fkReimbursement, costBalance,
wageHint, or the "Monthly costs" JSX section. These are cut per UI-SPEC.
