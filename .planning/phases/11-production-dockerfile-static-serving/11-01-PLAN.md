Create a new file at the repo root named `Dockerfile` with EXACTLY this content (preserve comments, blank lines, and indentation; final newline):

```dockerfile
# syntax=docker/dockerfile:1.6

# ── Stage 1: builder ────────────────────────────────────────────────────────
FROM node:22-slim AS builder
WORKDIR /app

# Layer: root lockfile (invalidates only when root package-lock.json changes)
COPY package.json package-lock.json ./
RUN npm ci

# Layer: server lockfile (invalidates only when server/package-lock.json changes)
COPY server/package.json server/package-lock.json ./server/
RUN npm ci --prefix server

# Layer: client lockfile (invalidates only when client/package-lock.json changes)
COPY client/package.json client/package-lock.json ./client/
RUN npm ci --prefix client

# Copy source (after deps so source-only changes don't trigger reinstall)
COPY server/ ./server/
COPY client/ ./client/

# Build: client first (Vite → client/dist), then server (tsc → server/dist)
RUN npm run build

# ── Stage 2: runtime ────────────────────────────────────────────────────────
FROM node:22-slim AS runtime
WORKDIR /app

# System packages: qpdf replaces the macOS Homebrew PATH hack removed from server/src/index.ts
# Single RUN combines update + install + cache cleanup so the layer stays small
RUN apt-get update && \
    apt-get install -y --no-install-recommends qpdf && \
    rm -rf /var/lib/apt/lists/*

# Production deps: root (currently zero prod deps; included for future-proofing)
COPY package.json package-lock.json ./
RUN npm ci --omit=dev

# Production deps: server only (client deps stay in builder stage; we only need client/dist output)
COPY server/package.json server/package-lock.json ./server/
RUN npm ci --omit=dev --prefix server

# Compiled output from builder
COPY --from=builder /app/server/dist ./server/dist
COPY --from=builder /app/client/dist ./client/dist

# Forms PDFs (static assets — not built, just copied)
COPY forms/ ./forms/

ENV NODE_ENV=production
ENV PORT=3001
EXPOSE 3001
CMD ["node", "server/dist/index.js"]
```

Critical correctness notes:
- Both `FROM` lines must be `node:22-slim` (D-02). Do NOT use `node:22-alpine` (musl libc native-binary issues per RESEARCH Pitfall) or `node:20-slim`.
- Three separate `npm ci` calls in builder stage (D-06) — root, server, client — each with its own COPY of `package.json + package-lock.json` BEFORE the COPY of source. This ordering is what enables Docker layer caching to skip reinstall when only source changes.
- Runtime stage runs `npm ci --omit=dev` for root and server only — NOT for client. Client devDependencies (Playwright, Vite, etc.) would bloat the runtime image by ~200MB; we only need the compiled `client/dist/` output, which is COPY'd from the builder stage (RESEARCH Pitfall 3).
- The apt-get RUN block must combine update + install + `rm -rf /var/lib/apt/lists/*` in a single layer (RESEARCH anti-pattern: "Missing rm -rf /var/lib/apt/lists/* after apt-get").
- `WORKDIR /app` must appear in BOTH stages before any COPY.
- CMD uses `["node", "server/dist/index.js"]` (exec form) — NOT shell form; matches `server/package.json` "start" script.
- Forms COPY: `COPY forms/ ./forms/` — copies repo-root `forms/` to `/app/forms`. Combined with the existing `path.join(__dirname, "../../forms")` resolver in server/src/index.ts (where `__dirname` = `/app/server/dist`), this resolves to `/app/forms` (D-01).

Do NOT add:
- A `USER node` directive (deferred to v1.0.3 security hardening per RESEARCH Security Domain note)
- A `HEALTHCHECK` (Azin handles this externally; out of phase scope)
- Any ARG / build args (not needed for this phase)
- Any docker-compose changes (not in this plan's files)

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| developer host → Docker build context | Files in repo root (and subdirectories not excluded by .dockerignore) are sent to the Docker daemon. Sensitive files (.env, .env.*) must NOT cross this boundary. |
| Docker daemon → registry / runtime image | Anything COPY'd in the runtime stage ships with the image. devDependencies and source code (.ts) must NOT be in the final image. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-11-01 | Information disclosure | `.env`, `.env.*`, `server/.env` files | mitigate | `.dockerignore` (Task 1) excludes `.env`, `.env.*`, and `server/.env` lines so they cannot enter the build context |
| T-11-02 | Tampering (attack surface) | devDependencies in runtime image | mitigate | Multi-stage Dockerfile (Task 3): builder installs full deps for tsc/vite; runtime installs only `npm ci --omit=dev` for root + server, and copies only compiled `client/dist` (no client devDeps) |
| T-11-03 | Information disclosure | `.git/` history (may contain past secrets per known PII leak in HANDOFF.md commit `9c38efc`) | mitigate | `.dockerignore` excludes `.git` so commit history never enters the image |
| T-11-04 | Information disclosure | `.planning/` directory (may contain internal design docs) | mitigate | `.dockerignore` excludes `.planning` |
| T-11-05 | Elevation of privilege | Container runs as root user | accept | Deferred to v1.0.3 security hardening per RESEARCH.md Security Domain note. Acceptable for v1.0.2 because Azin runs each tenant in an isolated VM. |
| T-11-06 | Denial of service | apt-get cache bloat → slow image pulls | mitigate | `rm -rf /var/lib/apt/lists/*` in same RUN as apt-get install (Task 3) |
</threat_model>
