## Overview

v1.0.1 was an urgent follow-on to the v1.0 MVP, scoped around the legally-required Swedish **lönespecifikation** (salary slip) for the anhörig-model assistants. Three adjacent foundation items were absorbed to avoid rework: (a) capture-missing-fields schema additions used by v1.2 + v1.3 downstream, (b) an `resolveEmployerRepresentation()` helper that closed a latent FK 3057/3059/SKV 4805 employer-name bug shared with the slip header, and (c) deletion of dead scheduling scaffolding (Settings card, openSlots table, self-book endpoints).

Phase 10 was a guardian-driven **real data entry + end-to-end verification** pass that exercised the full pipeline on live values rather than placeholders, closing the milestone with three clean PDFs (FK 3057, SKV 4805, salary slip) showing zero placeholder text.

### Issues Resolved

- **Latent employer-name bug:** FK 3057 / FK 3059 / SKV 4805 used `profile.guardianName` as the legal employer — silently wrong for adult brukare. Closed by `resolveEmployerRepresentation()` (Phase 8). Grep gate enforces zero direct `guardianName` references for employer field.
- **Dead scheduling scaffolding:** Settings "Scheduling" card + `open_slots` table + `/api/slots` + `/api/assistant/self-book` + `/api/assistant/open-slots` endpoints were unreachable from the IA. Removed in Phase 7.
- **Schema drift from v1.0:** 7 orphaned columns + 3 timestamptz declaration mismatches resolved during Phase 7 schema work.
- **FK 3057 encryption regression:** Phase 8's refactor moved `/fk3059` and `/4805` to `decryptAndFill` (qpdf) but missed `/fk3057`. Surfaced as HTTP 500 in 10-UAT Test 1, fixed inline in commit `8b93937`.
- **Statutory non-compliance (no salary slip):** Swedish labor law requires a written pay record per pay period. v1.0 shipped only bank-transfer references. v1.0.1 adds the lönespec PDF pipeline.
- **Main↔milestone divergence:** PR #7 was originally merge-blocked because `main` had 30 parallel commits (multi-family backend + clock-in/out + AssistantDetail + real OAuth) that the milestone branch never inherited. Reconciled in commit `e389a0d` per 6 explicit decisions; full audit in `MAIN-VS-MILESTONE-DIAGNOSIS.md` (now at `.planning/milestones/v1.0.1-MILESTONE-AUDIT.md`).

### Issues Deferred

- **Multi-family Settings UI** — Backend is fully wired on `main` (`/families`, `/link-existing`, `/link-status`, `/link-requests/{accept,decline}` + `assistantsApi.linkExisting/linkStatus`). The merge dropped main's UI per Decision #4 reversal; needs to be re-added in milestone's 2-section collapsible shape. Tracked as **Track B** in HANDOFF.md.
- **CodeRabbit hardening (6 HIGH-severity findings on PR #7)** — TOCTOU on clock-in, multi-table ops without transactions, missing UNIQUE on `assistantGuardianLinks`, JWT in query parameter logged, `e.message` leaked to clients. Most are pre-existing latent issues that the cumulative diff surfaced for the first time, not regressions introduced by v1.0.1. Tracked as **Track A** in `.planning/todos/pending/2026-04-25-v1.0.2-hardening-from-pr7-review.md` → planned for v1.0.2.
- **`hourlyRateOverride = 0.31` parsing bug** — likely Swedish decimal-comma issue in Settings input. Externally validated by CodeRabbit; tracked in HANDOFF Track C.
- **Plan 10-04 (FK decision fields gap-closure)** — recommended for DROP per `10-VERIFICATION.md`: `fk_decision_*` fields are schema-only with no PDF consumer in v1.0.1, so the residual `23123123123123` placeholder doesn't reach the guardian. Revisit if v1.2 SUBMIT introduces a consumer.
- **Pre-existing PII leak in `.planning/HANDOFF.md` history** — committed in `9c38efc`, low priority redaction.

### Technical Debt Incurred

- The Phase 9 route-integration tests use an in-memory db mock (mirrors `gcal.test.ts` precedent) rather than a live Postgres. Faster but means certain DB-level constraints (UNIQUE violations on race) are simulated, not exercised against the real driver.
- Plan 10-02 was superseded but its `10-02-PLAN.md` is kept in place as reference documentation. Future cleanups of `.planning/phases/` should preserve the superseded marker.
- The merge to `main` brought back some of `main`'s parallel work (multi-family backend, FK form fixes) without all of `main`'s frontend (Dashboard / Reports / Assistants / AssistantDetail pages were dropped per Decision #2 + #4). The dropped pages were superseded by milestone UI; if any feature is still needed, re-implement on the milestone IA.
