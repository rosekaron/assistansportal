## What Was Built (All 10 Plans)

### Plan 01 — DB Schema (commit 5fc085a, 2dfb91e)

- `clock_events` table: `id`, `assistant_id`, `guardian_id`, `clock_type`, `timestamp`, `ip`, `user_agent`, `verified`
- `assistant_guardian_links` table: `id`, `assistant_id`, `guardian_id`, `active`
- `clockTypeEnum` ("in"/"out") PostgreSQL enum
- `entries.verified` boolean column (default false) — canonical flag for clock-based vs manual entries
- `ClockEvent` and `AssistantGuardianLink` TypeScript inferred types exported from schema.ts
- Applied via direct pg DDL (drizzle-kit push blocked by pre-existing schema drift in production DB)

### Plan 02 — Clock-In/Out API (commit bb65934, 93036af)

- `POST /api/clock/in` — creates clock-in event; blocks if no active guardian link
- `POST /api/clock/out` — marks clock-in consumed; auto-creates `entries` row with `verified=true, reqStatus="approved"`
- `GET /api/clock/status` — returns `{ state: "clocked_in" | "clocked_out", activeEvent? }`
- All endpoints guarded by `requireAuth + requireAssistant`; `assistantId` always resolved server-side from JWT

### Plan 03 — Guardian Links API (commit fdd2d4b, d448177)

- `GET /api/guardian-links` — guardian lists all links with assistant names
- `POST /api/guardian-links` — guardian creates inactive link (invite)
- `GET /api/guardian-links/my-families` — assistant lists active families
- `POST /api/guardian-links/:id/accept` — assistant activates a link
- Role enforcement: guardian-only endpoints use `requireGuardian`; assistant-only use `requireAssistant`

### Plan 04 — Route IA Restructure (commit 8a5a62a, 6be5d17)

- `App.tsx`: 7 guardian routes replaced with 4 (`/home`, `/monthly`, `/records`, `/settings`) plus 9 legacy `<Navigate replace>` redirects
- `Layout.tsx`: 7-item nav replaced with 4-item nav (Home, Monthly, Records, Settings) using Lucide icons
- `RequireAssistant` guardian redirect fixed from `/dashboard` to `/home`

### Plan 05 — Home.tsx (commit f06b23d, 9201135)

- New page (469 lines): 7-day schedule grid, GCal status banner, FK-gated download, payroll pending count badge, mark-absent dialog
- FK download disabled when `invoicePending > 0 OR invoiceHours === 0`
- Mark-absent dialog calls `absenceApi.create()` and invalidates queries
- `/home` route wired in App.tsx

### Plan 06 — Monthly.tsx (commit 7a6eac5, 7fbaa26)

- New page (871 lines): 3-step compliance stepper — Daily reports → Payroll → FK forms
- Per-entry `verified` badge reads `entry.verified === true` (canonical DB column, not `source` heuristic)
- FK forms section (step 3) disabled with tooltip until both steps 1 and 2 complete
- Single shared `year`/`month` state drives all queries; ChevronLeft/Right month navigator
- `/monthly` route wired in App.tsx; `/reports`, `/payroll`, `/compliance` redirect here

### Plan 07 — Records.tsx (commit e25bbf4, f1e461e)

- New page (509 lines): read-only historical lookup with 3 tabs — Payroll, FK Submissions, Leave
- Payroll tab: 12-month Promise.all query, per-assistant rows, status badge
- FK Submissions tab: derived from payroll approval status (V1 approximation noted)
- Leave tab: assistant filter, VAB/sick balance cards, full absence history table
- No mutating buttons anywhere; Dashboard import removed from App.tsx
- `/records` route wired; `/leave` redirects here

### Plan 08 — Settings.tsx (commit fb1ff71)

- Assistants management section embedded: weekly hours budget bar, assistant cards with "View leave" link to `/records`, pending invites table, Add/Edit/Remove dialogs
- Static 3-step GCal setup guide card (collapsible `wizardOpen` toggle, no API calls)
- `absenceApi` and `AssistantAbsenceSummary` removed; replaced with link to `/records`

### Plan 09 — AssistantDashboard.tsx (commit 52176db, 6c82c41)

- `clockApi` (clockIn, clockOut, status) and `guardianLinksApi` (myFamilies) helpers added to `api.ts`
- AssistantDashboard full rewrite (450 lines): clock-in/out hero as primary action
- Live HH:MM:SS elapsed timer via `useEffect + setInterval` with cleanup
- Family selector shown only when `families.length >= 2`; selection persisted to sessionStorage
- Clock-out confirmation dialog shows start time, duration, shift report notice
- Proposals tab, Open slots tab, and all `submitReport`/`selfBook` mutations removed
- Reports tab is read-only; entries flow from clock-out automatically
