## Page Layout Contract

### Frånvaro Page (`/leave`)

Layout follows the established pattern from `Assistants.tsx` and `Dashboard.tsx`:

```
PageHeader (title + "Registrera frånvaro" button)
├── Balance panel (top row, 3 cards side by side)
│   ├── Per-assistant VAB balance card (remaining days / 120)
│   ├── Per-assistant sick leave YTD card (X dagar)
│   └── Summary card (total absences this year)
└── Absence records section
    ├── Filter row (assistant Select + type Select + month Select)
    └── Absence table (date range | assistant | type badge | created | delete button)
```

Content max-width: `max-w-5xl` (matches existing Layout.tsx main content area).
Padding: `px-8 py-8` (matches existing pages).

### Assistants Page Addition

Inside each assistant card's existing detail section, add a compact row below existing fields:

```
── Frånvaro [year] ─────────────────────────────────
VAB kvar: 118 dagar (of 120)   Sjukfrånvaro: 2 dagar
```

This is a read-only summary row, no interaction. Uses `SectionLabel` + small text at `text-sm`.

## Interaction Contract

### Record Absence Flow
1. Guardian clicks "Registrera frånvaro" button in PageHeader
2. `Dialog` opens (animation: `zoom-in-95` — already in `DialogContent`)
3. Form fields:
   - **Assistent** — `Select` with all assistant names + "Alla assistenter" option (maps to null assistantId)
   - **Typ av frånvaro** — `Select` with 4 options using Swedish labels: "Sjukfrånvaro", "VAB (vård av barn)", "Semester", "Övrigt"
   - **Startdatum** — `Input` type `date`
   - **Slutdatum** — `Input` type `date` (must be >= startdatum; validate client-side before submit)
4. CTA inside dialog: "Spara frånvaro" (`Button` default, full width)
5. On success: dialog closes, absence list re-fetches (React Query invalidation), balance cards re-fetch
6. On server error: display error message below CTA inside dialog — "Kunde inte spara frånvaro. Kontrollera datumen och försök igen."

### Delete Absence Flow
1. Guardian clicks delete icon button on a table row
2. Row expands inline to show: "Bekräfta radering?" + "Ja, radera" + "Avbryt" (no modal overlay)
3. On "Ja, radera": call `DELETE /api/absences/:id`, invalidate queries
4. Note: deleting an absence does NOT automatically restore cancelled shifts (per CONTEXT.md D-02). No UI feedback about cancelled shifts is needed.

### Filter Interaction
1. All three filters (assistant, type, month) operate client-side on the fetched absence list
2. Filters are independent — each reduces the visible rows without re-fetching
3. "Alla" / empty value resets that filter dimension
4. No loading spinner needed — filtering is synchronous on the already-fetched array

### Clock-In Block (assistant-facing)
- The assistant UI does not need a new page or component
- The server returns `409` with `error: "Assistant has an active absence on this date"` when a blocked action is attempted
- The existing assistant-facing error display handles this response — no new UI needed for Phase 2

## Accessibility Requirements

- All icon-only buttons must have `aria-label` (delete button: `aria-label="Radera frånvaro"`)
- Dialog uses `DialogTitle` — already provides accessible name for the modal
- Select components use `Label` associated via `htmlFor` + `id` pairing on the `SelectTrigger`
- Form date inputs: `<Label htmlFor="startDate">Startdatum</Label><Input id="startDate" type="date" />`
- Absence type badge colors are not the only indicator — text label is always present inside badge
- Focus order in dialog: Assistent Select → Typ Select → Startdatum Input → Slutdatum Input → "Spara frånvaro" Button → Close X
- VAB balance threshold colors (green/amber/red) are not the only indicator — the number and "X dagar kvar av 120" text is always shown
- All interactive elements must receive focus via Tab key (no `tabIndex="-1"` on reachable controls)
