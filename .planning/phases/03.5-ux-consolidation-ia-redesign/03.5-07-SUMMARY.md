# Phase 3.5 Plan 07: Records Page Summary

**One-liner:** Read-only historical lookup page with three tabs (Payroll, FK Submissions, Leave) using year-based filtering and per-assistant absence balance cards.

## What Was Built

**Records.tsx** (509 lines) — a fully read-only historical page with:

- **Year selector** in PageHeader (ChevronLeft/ChevronRight navigation, max = current year)
- **Payroll tab**: queries all 12 months for the selected year via `Promise.all`, groups results by month (descending), renders per-assistant rows showing billable hours, gross pay, total employer cost, and status badge (Approved = success, Draft = warning)
- **FK Submissions tab**: derives "cycle complete" months from payroll approval status (all records in month must be `status === "approved"`); shows month, "Cycle complete" badge, latest `approvedAt` date. Includes V1 approximation notice.
- **Leave tab**: assistant filter dropdown ("All assistants" or specific), per-assistant balance cards (VAB remaining with progress bar + colour coding, sick days YTD), full absence history table sorted by startDate descending with type labels (Sick leave, VAB, Holiday, Other)
- **Empty state**: "No records yet. Data appears here once you complete a monthly cycle."
- **No mutating buttons** anywhere on the page — no approve, reject, generate, or delete actions

**App.tsx** changes:
- Replaced Dashboard stub on `/records` with `RecordsPage`
- Removed `Dashboard` import (no longer referenced)
- `/leave → /records` redirect preserved

## Deviations from Plan

None — plan executed exactly as written.

## Known Stubs

None. All data is wired to live APIs:
- `payrollApi.list(month)` via Promise.all over 12 months
- `absenceApi.list()` filtered client-side by year
- `absenceApi.balance(assistantId)` per assistant via separate useQuery hooks
- `assistantsApi.list()` for name/avatar resolution

## Threat Flags

No new threat surface introduced. Records.tsx is read-only (T-3.5-20 confirmed: no mutations). All data is scoped to the guardian's household via existing RequireGuardian middleware (T-3.5-19 accepted).
