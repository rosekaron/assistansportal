<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client → /api/payroll | Unauthenticated or assistant-role callers must be rejected; guardian-scoped data must not leak |
| client → /api/payments | Same boundary; delete operation must be scoped to the authenticated guardian's data |
| payroll generate | Month parameter from client body; must be validated before being used in DB query |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-01 | Spoofing | GET /api/payroll, POST /api/payroll/generate, POST /api/payroll/:id/approve | mitigate | requireAuth middleware validates JWT on every request; tested by Wave 0 stubs (401 on missing token) |
| T-03-02 | Elevation of Privilege | All /api/payroll and /api/payments routes | mitigate | requireGuardian middleware rejects assistant-role JWT with 403; tested by Wave 0 stubs (403 on assistant token) |
| T-03-03 | Tampering | POST /api/payroll/generate body | mitigate | Zod schema validates month format `/^\d{4}-\d{2}$/` before any DB operation; invalid input returns 400 |
| T-03-04 | Tampering | POST /api/payroll/:id/approve — approve already-approved record | mitigate | Route checks current status before transition; returns 409 if already "approved" (per D-13) |
| T-03-05 | Information Disclosure | GET /api/payroll returns all records | mitigate | Single-tenant deployment per D-03; route executes without guardianId column filter — data isolation enforced at auth level via requireGuardian (same pattern as entries, absences) |
| T-03-06 | Tampering | DELETE /api/payments/:id — deleting another guardian's payment | accept | Single-tenant deployment; only one guardian user exists per deployment; no cross-guardian data risk in v1 |
| T-03-07 | Repudiation | No audit trail on payroll approval | accept | D-13 explicitly defers audit log to Phase 4 (AGI needs it); status lock (draft→approved) provides minimum traceability for Phase 3 |
| T-03-08 | Denial of Service | POST /api/payroll/generate called twice for same month | mitigate | Route must check for existing payroll_records row for (assistantId, month) before inserting; return 409 if already exists |
</threat_model>
