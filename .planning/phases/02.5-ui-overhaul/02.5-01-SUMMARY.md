# Phase 2.5 Plan 01: Tailwind ESM Fix Summary

**One-liner:** Convert `tailwind.config.js` from CJS `require()` to ESM `import` so Tailwind JIT generates utility classes in an `"type": "module"` project.

---

## What Was Built

### The Fix

Two line changes in `client/tailwind.config.js`:

1. **Line added at top (line 1):**
   ```js
   import tailwindAnimate from "tailwindcss-animate";
   ```

2. **Line replaced (was line 52, now line 54):**
   ```js
   // Before:
   plugins: [require("tailwindcss-animate")],
   // After:
   plugins: [tailwindAnimate],
   ```

All other content in the file is unchanged — theme extensions, content paths, colors, borderRadius, fontSize, keyframes, animation, boxShadow, and the export default structure.

### Root Cause

`client/package.json` declares `"type": "module"`, placing the entire `client/` directory in an ESM context. The synchronous `require()` call is illegal in ESM. When Tailwind v3's PostCSS plugin attempted to load the config, it received an error and silently fell back to a bare default config with no `content` paths. JIT therefore generated only the base reset layer — exactly the 51-rule symptom.

### Build Verification

- `npm run build` exits 0 in `client/` — 1743 modules transformed, 37.36 kB CSS generated
- `grep -n "import tailwindAnimate" client/tailwind.config.js` returns line 1
- `grep -n "require(" client/tailwind.config.js` returns no output
